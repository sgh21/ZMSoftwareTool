# 机器人定位精度监控页

当前阶段先确认布局与交互，不接入相机、控制器、标定或评估算法。

## 监控依据

1. 采用已标定的相机到被评估末端（TCP）的手眼变换，不要求完整机器人运动学模型。手眼参数与初始测量基准分别管理，保留参数版本。
2. 机器人投入使用前，按固定程序、固定位姿拍摄靶标，保存初始观测基准。
3. 后续每次评估重复相同程序、位姿和靶标，通过视觉观测误差反映末端定位误差。机器人运动由原设备控制软件执行。
4. 展示 X、Y、Z 位置指标，以及反映整体定位水平的位置距离指标；不评价姿态角，不涉及主轴回转精度。
5. 根据当前评估结果，预测实际加工点位的 XYZ 和距离指标。加工点位与拍照观测点分别管理，预测值不能说成在这些加工点位的实测值。

视觉相对计算的依据来自原工程 `../SoftwareTools/AGENTS.md`“已确认的视觉末端定位监控原理”：相机与末端刚性连接，靶标相对基座固定，视觉输入包含完整旋转和平移，即使页面只展示位置指标也不能忽略视觉旋转。

用 `H` 表示相机到末端的手眼变换，`V_0`、`V_i` 表示基准、当前的靶标到相机变换。相对末端变换为 `ΔT_E = H V_0 V_i⁻¹ H⁻¹`，其平移 `p_ΔE` 在初始末端坐标系中表达。用户指定默认展示机器人基坐标系下的 XYZ，因此还需每个测量点的初始末端朝向 `R_E0`，按 `Δp_B = R_E0 p_ΔE` 转换；该朝向应关联到基准数据，具体获取接口待接入时确定，界面不增加坐标系选项。缺失朝向时不能把末端系分量直接当作基坐标分量。

单测量点的距离为 `||Δp_B|| = ||p_ΔE||`。这代表相对基准的位置偏移，不直接等同于当前绝对定位误差，也不等同于前后误差模长之差。跨点汇总、阈值及未测加工点的预测方法仍待确认；不将各轴独立最大值直接合成为距离，也不声称仅靠手眼参数即可预测所有加工点。本轮只更新设计约定，不实现这些算法。

## 固定区域编号

编号沿用用户 2026-09-24 标注截图，后续说“区域 N”按下表理解。编号仅用于沟通、文档和代码定位，界面不显示数字标号或编号说明。

整体采用左侧结果、右侧设置，宽度约 65:35。字体、图标、间距与控件随窗口统一缩放；右栏设计最小宽度 332，同样参与缩放。左侧结果面板与明细表延伸至页面底部。采集、导入、清空日志、评估四个按钮在右侧日志下方同排，嵌入右面板，不另加外框或横跨页面的底栏。小窗口可纵向滚动查看下部内容。

| 编号 | 内容 | 操作与职责 |
| --- | --- | --- |
| 1 | 机器人定位精度；本次评估/基准批次；X、Y、Z、距离四列指标及阈值；评估结论 | 四项指标的标题、数值、单位、阈值文字与曲线同色：X 蓝、Y 青、Z 棕、距离紫。历史入口移至左侧底部；无结果时为“—”及“尚未评估” |
| 2 | 多次评估的定位变化趋势 | 图例与下拉框在同一行靠右，图例位于下拉框左侧。可选择“XYZ 分量”三条曲线或“位置距离”单曲线；纵轴 mm，横轴评估时间/批次。只展示传入结果，无记录时提示 |
| 3 | 加工点位预测、观测图像、报警与维护三个详情页签 | 预测表列为点位、X、Y、Z、距离、判定；底部“历史记录”与“展开明细”并排。图像可切换本次/基准；报警和维护记录保留入口 |
| 4 | 机器人手眼参数：加载状态、相机到末端（TCP）的变换关系、参数版本 | 加载手眼参数、查看手眼参数；后续读取既有旋转和平移参数，不加载整机模型，不执行手眼标定 |
| 5 | 测量基准：批次、采集时间 | 建立基准、选择基准；后续保存初始视觉观测，关联拍摄程序、测量点编号、手眼参数版本及初始末端朝向 |
| 6 | 右侧日志下方的采集、导入入口 | “采集靶标”“导入观测”与“清空日志”“评估精度”同排；不放“本次观测”标题和状态块，不另占整页栏位 |
| 7 | 判定与点位设置：XYZ/距离阈值、加工点位数量 | 阈值弹窗仅有 X、Y、Z、距离四个输入，默认按机器人基坐标表达，不提供坐标系选项；点位管理支持新增、删除、编辑编号/理论 XYZ、上下移和顺序编号 |
| 8 | 运行日志 | 显示时间、INFO/WARN/ERROR 与消息，可选择复制、滚动和清空；清空按钮放在日志下方，与评估同排，不放在标题旁 |

“评估精度”后续读取手眼参数、基准和本次观测，生成当前指标；加工点位预测待确定方法后接入。四个操作按钮与历史、明细等查看入口统一使用蓝底白字；手眼参数、基准、阈值和点位等设置按钮保留白底。底部按钮使用四字文案，方便小窗口同排显示。

## 当前交互边界

- 加工点位编辑是当前会话的界面配置。双击单元格修改编号和理论 XYZ，坐标可先留空；编号不能为空或重复，非空坐标必须是有效数值。点击“应用”更新区域 3 和区域 7 的数量；“取消”不改动已应用配置。重启后不保留。
- 点位理论坐标默认采用机器人基坐标系，是输入而非预测结果。新增点位后，X、Y、Z、距离预测值均为“—”，判定为“待预测”。
- 趋势控件 `PositionTrendChart.set_history(records)` 接收已计算的 `label`、`X`、`Y`、`Z`、`distance`；缺失指标为 `None`。只负责绘图，不计算指标或生成演示数据，当前没有历史数据源。
- 区域 6 的采集/导入，以及手眼参数加载/查看、基准和评估等未接入操作，在区域 8 提示尚未实现、未执行任务，不产生成功状态。日志记录本次运行的实际界面事件，不持久化、不声称已连接算法。
- 阈值输入仍为布局预览，关闭后不保存；历史、报警、维护表均为空。无结果不显示“正常”，也不编造报警和维修结论。
- 三个顶层精度选项卡和返回逻辑保留，另外两页仍为“待开发”。页面沿用深色微软雅黑、白色面板；蓝色用于操作，绿色用于顶层精度选项卡选中状态。
